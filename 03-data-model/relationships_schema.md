# Схема связей между сущностями информационной модели

Схема иллюстрирует, как входящие данные преобразуются в нормативные сущности базы знаний:

```text
[Входной черновик] (ЧЕРН-ХХХ)
       │
       ▼ порождает
[Решение агента] (РЕШ-ХХХ) ──── связывается с ────► [Журнал действий] (ЛОГ-ХХХ)
       │
       ├─────────────────────────────────┐
       ▼ создает                         ▼ использует для валидации
[Регламент (Черновик v0.1)]       [Должность / Роль] (ДОЛЖ-ХХХ из РЕГ-003)
 (РЕГ-ХХХ-ЧЕРНОВИК)                      ▲
       │                                 │
       │ (после ручного утверждения)     │
       ▼                                 │
[Утвержденный регламент] (РЕГ-ХХХ) ──────┤
       │                                 │
       ▼ порождает                       │
[Карточка регламента] (КАРТ-РЕГ-ХХХ) ────┘
       │
       ▼ агрегируется в
[Реестр регламентов компании] (РЕЕСТР-00)
```

---

## Описание типов связей

1. **«Черновик» ➔ «Решение агента»:** связь `1 к 1`. Каждый черновик получает ровно одну карточку решения.
2. **«Решение агента» ➔ «Журнал действий»:** связь `1 ко Многим`. В ходе обработки одного черновика фиксируется последовательность событий.
3. **«Регламент» ➔ «Должность»:** связь `Многие ко Многим`. В регламенте участвуют несколько штатных единиц, каждая штатная единица может участвовать во многих регламентах.
4. **«Утвержденный регламент» ➔ «Карточка регламента»:** связь `1 к 1`. Для каждого утвержденного документа существует ровно одна сжатая карточка для быстрой сверки.
5. **«Карточки регламентов» ➔ «Реестр компании»:** связь `Многие к 1`. Все карточки сводятся в единую матрицу владения процессами.
