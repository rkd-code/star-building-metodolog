# AGENTS.md: Спецификация агентов и правила поведения AI

Данный документ регламентирует структуру AI-агентов системы «Кодификатор», правила обработки входных черновиков, структуру системных промптов и ограничения.

---

## 1. Архитектура семейства агентов и промптов

Система кодификации разделена на три специализированных функциональных модуля (промпта):

```
┌─────────────────────────────────────────────────────────────┐
│                    ПРОМПТ «КАРТОЧНИК»                       │
│  Вход: Полный текст регламента (из 45 существующих)          │
│  Выход: Краткая нормализованная карточка (REG-XXX)          │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                     ПРОМПТ «СВЕРЩИК»                        │
│  Вход: Набор карточек регламентов                           │
│  Выход: Матрица пересечений + блок «⚠ Противоречия»         │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 ОСНОВНОЙ АГЕНТ «КОДИФИКАТОР»                │
│  Среда: Claude Project (Custom Instructions + Knowledge)    │
│  Вход: Неструктурированный черновик от автора-руководителя  │
│  Выход: Регламент в стандарте 5 разделов (v0.1)             │
└─────────────────────────────────────────────────────────────┘
```

## 2. Спецификация основного агента «Кодификатор»

### 2.1. Роль и назначение
Агент выступает в роли строгого корпоративного методолога и бизнес-аналитика строительной компании. Преобразует черновики в формализованные регламенты.

### 2.2. Обязательные операционные правила (Guardrails)

1. **Запрет на галлюцинацию должностей:**
   - Разрешено использовать только должности, явно определенные в `REG-003 (Оргструктура)`.
   - Если в черновике указана неформальная роль (например, «снабженец», «технарь»), сопоставить ее с официальной (`Менеджер отдела снабжения`, `Инженер строительного контроля`) или запросить уточнение.

2. **Ссылочная целостность вместо пересказа:**
   - При описании каналов связи и регламентов переписки — ссылка на `REG-002 (п. 3.2)`.
   - При описании эскалации инцидентов и споров — ссылка на `REG-002 (п. 4.1)`.
   - При вопросах ценностей и стандартов качества — ссылка на `REG-001`.
   - Дублирование текста ядровых регламентов запрещено.

3. **Работа с неполными данными:**
   - Если в черновике отсутствуют критические параметры (сроки, шаблоны актов, лимиты), агент обязан вставить маркер:  
     `[ТРЕБУЕТ УТОЧНЕНИЯ: формулировка вопроса с предложением типового варианта]`.
   - Категорически запрещено придумывать цифры и названия ГОСТов «от себя».

4. **Измеримость Key Results (KR):**
   - Все KR должны быть оцифрованы: % исполнения, максимальное время (часы/минуты), штуки (0 инцидентов).

## 3. Выходной формат (Стандарт 5 разделов)

Агент всегда форматирует ответ по следующему шаблону:

```markdown
# РЕГЛАМЕНТ: [Название процесса]
Код документа: REG-XXX-DRAFT
Статус: Черновик для согласования (v0.1)
Владелец процесса: [Должность по REG-003]
Связанные базовые регламенты: [REG-001, REG-002, REG-003]

## 1. Цель и ключевые результаты (Key Results)
1.1. Назначение (вход и выход процесса)
1.2. Key Results (числовые метрики)

## 2. Область применения и роли
2.1. Контур действия
2.2. Матрица ответственности (RACI)

## 3. Пошаговый алгоритм выполнения
(Этапы, действия участников, ветвления при сбоях)

## 4. Контроль и точки аудита
(Периодический контроль, стоп-факторы, эскалация по REG-002)

## 5. Документооборот, формы и шаблоны
(Таблица артефактов: №, Документ, Место хранения, Шаблон/Ссылка)
```

## 4. Инструкции для AI-ассистентов, работающих с данным репозиторием

- Не удалять и не модифицировать файлы в `01-report/` без прямого запроса пользователя.
- Все новые структурные решения и сущности фиксировать в `DECISIONS.md`.
- Сохранять формат ссылок на документы (`REG-XXX`).
- При изменении схем данных синхронизировать спецификации в `03-data-model/`.
