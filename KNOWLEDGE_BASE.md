# KNOWLEDGE_BASE.md: Структура и регламент ведения базы знаний

Данный документ определяет архитектуру базы знаний, входящей в контекст Claude Project (`Project Knowledge`), правила хранения файлов и структуру связей между документами компании.

---

## 1. Структура хранения базы знаний на диске

База знаний организуется в три изолированных каталога:

```text
knowledge_base/
├── 00_РЕЕСТР/
│   └── reestr-reglamentov.md         # Сводная таблица регламентов + Матрица владения процессами
│
├── 01_КАРТОЧКИ/                      # Сжатые метаданные для быстрого поиска и сверки
│   ├── card_REG-001_kodeks.md
│   ├── card_REG-002_kommunikacii.md
│   ├── card_REG-003_orgstruktura.md
│   └── card_REG-004_vhodnoy_kontrol.md
│
└── 02_ПОЛНЫЕ-ТЕКСТЫ/                 # Полные утвержденные тексты регламентов
    ├── full_REG-001_kodeks.md
    ├── full_REG-002_kommunikacii.md
    ├── full_REG-003_orgstruktura.md
    └── full_REG-004_vhodnoy_kontrol.md
```

---

## 2. Обязательное ядро базы знаний (Core Group)

Ядро загружается в `Project Knowledge` всегда и является фундаментом для валидации любых новых черновиков:

| ID документа | Название регламента | Назначение в базе знаний | Обязательные разделы для ссылок |
|---|---|---|---|
| **`REG-001`** | **Кодекс компании** | Ценности, принципы качества, этика, ответственность | Раздел «Ответственность за качество» |
| **`REG-002`** | **Регламент коммуникаций** | Каналы связи (Telegram, email, звонки), сроки ответов, матрица эскалации | П. 3.2 «Оперативные чаты», П. 4.1 «Эскалация инцидентов» |
| **`REG-003`** | **Оргструктура компании** | Реестр утвержденных должностей, подчиненность, зоны ответственности | Штатная сетка (Служба строительства, Снабжение, Технадзор и др.) |

---

## 3. Критерии отбора пилотных документов (5–10 регламентов)

Для запуска MVP v1.0 отбираются:
1. **Обязательное ядро (3 документа):** `REG-001`, `REG-002`, `REG-003`.
2. **Операционные регламенты (2–7 документов):**
   - Процессы, чаще всего вызывающие споры и конфликты на стройплощадках (например, входной контроль материалов, приемка скрытых работ, передача фронта работ).
   - Процессы с высокой частотой генерации черновиков от руководителей.

---

## 4. Формат карточки регламента (`01_КАРТОЧКИ`)

Каждая карточка формируется промптом «Карточник» по следующему шаблону:

```markdown
# КАРТОЧКА: [ID] [Название]

- **ID:** REG-XXX
- **Владелец процесса:** [Должность по REG-003]
- **Цель процесса:** [1 предложение]
- **Вход процесса:** [Триггер, документы, материалы]
- **Выход процесса:** [Результат, артефакты]
- **Ключевые роли:** [Список ролей по REG-003 с функциями]
- **Связанные документы:** [Прямые ссылки на REG-YYY]
- **Точки контроля и сроки:** [Контрольные точки и SLA]
```

---

## 5. Протокол обновления базы знаний

1. **Добавление нового регламента:**
   - После утверждения финальной версии руководством документ помещается в `02_ПОЛНЫЕ-ТЕКСТЫ`.
   - Через промпт «Карточник» генерируется файл в `01_КАРТОЧКИ`.
   - В `00_РЕЕСТР/reestr-reglamentov.md` добавляется строка с ID и матрицей владения.
   - Обновленные файлы синхронизируются с `Project Knowledge` в Claude Project.
2. **Периодический аудит (v2.0):**
   - Раз в 6 месяцев все карточки прогоняются через промпт «Сверщик» для выявления устаревших или противоречащих друг другу пунктов.
