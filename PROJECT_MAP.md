## 2. Жизненный цикл регламента (Data Flow Pipeline)

```
[Автор / Руководитель]
       │
       ▼ (Сырой текст, голосовая заметка, черновик)
[Claude Project: Агент «Кодификатор»] ◄── [Project Knowledge: Реестр, Карточки, Ядро]
       │
       ▼ (Проверка ролей по REG-003, связей с REG-001/002, разметка [ТРЕБУЕТ УТОЧНЕНИЯ])
[Проект регламента v0.1 (5 разделов)]
       │
       ▼ (Вычитка методологом / Заказчиком)
[Устранение пометок [ТРЕБУЕТ УТОЧНЕНИЯ]]
       │
       ▼ (Согласование руководством вне агента)
[Утвержденный регламент REG-XXX]
       │
       ▼ (Прогон через промпт «Карточник»)
[Новая карточка в 01_КАРТОЧКИ] ──► [Обновление reestr-reglamentov.md]
```

## 3. Матрица перехода версий (Scope Matrix)

| Компонент / Функция | Версия v1.0 (MVP) | Версия v2.0 (Target) |
|---|---|---|
| **Среда выполнения** | Claude Project (Web UI) | Slack (Claude Tag) / Telegram Bot |
| **Объем базы знаний** | 5–10 пилотных документов | Все 45 регламентов компании |
| **Управление реестром** | Заказчик лично вручную | Делегированный сотрудник + CLI-утилиты |
| **Аудит базы знаний** | 1 разовый проход «Сверщика» | Регулярный авто-аудит каждые 6 месяцев |
| **Публикация регламентов** | Ручная выгрузка | Авто-экспорт в Bitrix24 / 1С:ДО / Confluence |
| **Целевые пользователи** | Методолог + узкий круг руководителей | Линейные прорабы, субподрядчики, все службы |

## 5. Сервис тестирования сотрудников

```text
29-employee-testing-service/
├── README.md                     # Концепция «Экзаменатора Star Building»
├── DATA_MODEL.md                 # Вопросы, программы, попытки, результаты, аудит
├── IMPORT_RULES.md               # Проверка и загрузка банка
├── build_question_bank.py        # Генератор шаблона
├── question_bank_template.xlsx   # Емкость 500 вопросов / 3000 вариантов
├── source_pool_001.docx          # Первый исходный пул
├── import_pool_001.py            # Воспроизводимый импорт
├── question_bank_pool_001.xlsx   # 102 распределенных вопроса
└── POOL_001_IMPORT_REPORT.md      # Источники, риски и пробелы
```

Сервис использует только утвержденные нормативные источники, формирует тесты по официальным должностям и сохраняет версии вопросов внутри завершенных попыток. Интеграции с Битрикс24 и Telegram запланированы после пилота.

### Автономный интерфейс

```text
30-employee-testing-html/
├── index.html                    # Готовая автономная платформа
├── build_platform.py            # Сборка из Excel-банка
├── test_build_platform.py       # Проверки данных и сборки
├── test_browser.py              # Сквозная проверка в Chromium
└── README.md                     # Запуск, функции и ограничения
```

`index.html` содержит интерфейс сотрудника и кабинет РОПа. Для пилота данные хранятся в браузере; промышленная версия требует серверной базы и авторизации.
