# Каталог внешних систем и интерфейсов интеграции

---

## ЧАСТЬ 1. Интеграции первой версии (v1.0 MVP)

### 1. Веб-интерфейс проекта (Claude Project)
- **Передаваемые данные:** Системные инструкции методолога, файлы базы знаний (`РЕГ-001`..`005`, реестр, карточки).
- **Получаемые данные:** Текст черновика от автора-руководителя, запросы на доработку.
- **Способ подключения:** Браузерный доступ пользователей через защищенный веб-интерфейс.
- **Разрешенные действия:** Чтение базы знаний проекта, генерация проекта регламента (версия 0.1), ответы на уточняющие вопросы.
- **Права доступа:** Только участники пилотной группы с правами авторов проекта.
- **Возможные ошибки:** Превышение лимита символов контекста, временный сбой сервиса.
- **Поведение при недоступности:** Повтор запроса после восстановления сервиса.
- **Подтверждение человеком:** **Обязательно.** Все сгенерированные тексты проверяются методологом вручную.

### 2. Локальное файловое хранилище сервера
- **Передаваемые данные:** Файлы регламентов (`02_ПОЛНЫЕ-ТЕКСТЫ`), карточки (`01_КАРТОЧКИ`), реестр (`00_РЕЕСТР`).
- **Получаемые данные:** Чтение файлов для формирования контекста и экспорта.
- **Способ подключения:** Прямой доступ к локальной файловой системе сервера `/home/roman/`.
- **Разрешенные действия:** Чтение, создание новых файлов регламентов, обновление реестра.
- **Права доступа:** Локальный пользователь `roman` (права `750` / `600`).
- **Возможные ошибки:** Нехватка места на диске, ошибки прав доступа.
- **Поведение при недоступности:** Аварийная остановка записи с фиксацией ошибки в журнале.
- **Подтверждение человеком:** Не требуется для локального чтения; создание/перезапись контролируется системой версий Git.

## ЧАСТЬ 2. Интеграции следующих версий (v2.0+)

### 3. Корпоративный мессенджер Telegram (Бот и каналы объектов)
- **Получаемые данные:** Текстовые и голосовые сообщения с черновиками от прорабов и линейных руководителей.
- **Передаваемые данные:** Готовые проекты регламентов, запросы на уточнение параметров, уведомления об утверждении.
- **Способ подключения:** Программный интерфейс Telegram Bot API (HTTPS / вебхуки).
- **Разрешенные действия:** Прием входящих сообщений, отправка файлов и текстовых ответов в авторизованные чаты.
- **Права доступа:** Авторизация по белому списку идентификаторов пользователей и чатов компании.
- **Возможные ошибки:** Блокировка токена, таймаут соединения, сбой распознавания голосовых сообщений.
- **Поведение при недоступности:** Накопление очереди сообщений с повторной отправкой при восстановлении связи.
- **Подтверждение человеком:** Не требуется для приема черновика; публикация в общий канал объекта — **только после подтверждения методологом**.

### 4. Корпоративный портал и база знаний (Битрикс24 / Корпоративная Wiki)
- **Передаваемые данные:** Утвержденные регламенты в формате HTML/Markdown, метаданные, матрицы ответственности.
- **Получаемые данные:** Статусы ознакомления сотрудников с новыми регламентами, комментарии.
- **Способ подключения:** Защищенный REST API портала Битрикс24.
- **Разрешенные действия:** Создание и обновление статей в корпоративной базе знаний, назначение задач на ознакомление.
- **Права доступа:** Сервисная учетная запись с правами публикации в разделе «Регламенты и стандарты».
- **Возможные ошибки:** Ошибка авторизации по токену, сбой структуры разделов базы знаний.
- **Поведение при недоступности:** Повторные попытки через экспоненциальную паузу, алерт администратору.
- **Подтверждение человеком:** **Обязательно.** Автоматическая публикация без визы руководства запрещена.

### 5. Система электронного документооборота (1С:ДО / СЭД)
- **Передаваемые данные:** Официальные карточки регламентов, тексты для согласования, маршруты визирования.
- **Получаемые данные:** Статусы согласования руководителями, номера и даты приказов об утверждении.
- **Способ подключения:** Веб-сервисы SOAP / OData / REST API 1С.
- **Разрешенные действия:** Инициация процесса согласования документа, чтение статусов подписания.
- **Права доступа:** Сертификат безопасности или сервисный пользователь с правами инициатора документов.
- **Возможные ошибки:** Блокировка сессии в 1С, несовпадение справочников подразделений.
- **Поведение при недоступности:** Постановка задачи в локальную очередь до восстановления контура 1С.
- **Подтверждение человеком:** **Обязательно.** Подписание выполняется руководителями через личные электронные подписи.
