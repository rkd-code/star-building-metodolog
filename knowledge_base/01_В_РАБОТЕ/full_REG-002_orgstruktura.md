# ЛИСТ: 04_Правила модели


| ПРАВИЛА ЦЕЛЕВОЙ ОРГМОДЕЛИ |  |  |  |

| Принцип | Правило | Зачем | Статус |

| 1. Один владелец результата | У каждого сквозного результата один accountable owner; остальные — функции поддержки. | Убирает пересечения и «ничьи» зоны. | Целевая модель |

| 2. Разделение Revenue / Delivery / Cash | Commercial владеет продажей и обещанием клиенту; PMO/Delivery — исполнением проекта; CFO — Cash и финансовым контролем. | Снижает конфликт между продажей, стройкой и финансами. | Целевая модель |

| 3. Линейный контур объекта | Начальник участка → мастер/прораб → рабочий персонал. PM отвечает за проектный результат, а не за микроменеджмент рабочих. | Ускоряет управление объектом. | Целевая модель |

| 4. Производство отдельно от стройки | Производственный цех выпускает продукт; стройка монтирует/исполняет объект. Связь через PMO/SCM. | Разделяет разные типы операций. | Целевая модель |

| 5. Shared Services | Finance, HR, IT, Legal, Security — корпоративные центры экспертизы с сервисными SLA для бизнеса. | Не дублировать функции в каждом подразделении. | Целевая модель |

| 6. Масштабирование по workload | Новые FTE открываются по объёму работы, а не автоматически по росту выручки. | Контроль управленческой «толщины». | Целевая модель |

| 7. Не придумывать отсутствующие роли | В источниках производство описано как 10 участков, но конкретные рабочие профессии не перечислены. Их состав нужно определить отдельным штатным нормированием. | Избегаем ложной точности. | Требует доработки |

| 8. ПТО масштабируется по сложности | Инженеры ПТО/сметчики/геодезисты добавляются по числу крупных объектов и фактической загрузке. | Сохраняем прямую зависимость от проектного портфеля. | Целевая модель |

| 9. Decision rights | Для спорных решений используется RAPID/RACI: кто рекомендует, кто решает, кто исполняет, кто даёт входные данные. | Сокращает согласования. | Целевая модель |
