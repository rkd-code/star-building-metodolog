# 33 — Реестр файлов и граф знаний виртуальной машины

## Назначение

Система формирует единые исходные данные, по которым агенты определяют:

- какие рабочие файлы существуют;
- где расположен каждый файл;
- к какому проекту он относится;
- что содержится в файле;
- как файл связан с проектом.

## Канонические результаты

Папка: `output/`.

- `file_inventory.xlsx` — основная удобная таблица;
- `file_inventory.csv` — табличный обменный формат;
- `file_inventory.jsonl` — полный очищенный текст каждого файла для агентов;
- `file_graph.json` — машиночитаемый граф «проект → файл»;
- `file_graph.html` — автономный обозреватель графа;
- `excluded_files.csv` — прозрачный перечень исключений;
- `inventory_report.json` — контрольные показатели сборки.

## Поля реестра

Для каждого файла сохраняются путь, название, проект, тип, размер, дата изменения, контрольная сумма SHA-256, краткое описание, извлеченное содержимое и число скрытых секретных фрагментов.

Excel ограничивает одну ячейку 32 767 знаками. Поэтому длинное содержимое сокращается только в Excel, а полный очищенный текст остается в `file_inventory.jsonl`.

## Охват

Обрабатываются рабочие и содержательные файлы внутри `/home/roman`: Markdown, текст, Python, HTML, JSON, YAML, CSV, сценарии, Excel и Word.

Исключаются:

- `.git`, `.hermes`, `.ssh`, `.gnupg`, `.config`, `.cache`, `.codex`;
- виртуальные среды, зависимости и кэши;
- архив переписки;
- журналы и учетные файлы;
- двоичные и неподдерживаемые форматы;
- результаты самой инвентаризации и канонические выходы Graphify.

Значения, похожие на ключи, токены, пароли и закрытые ключи, заменяются на `[REDACTED]`.

## Обновление

Автоматическая задача каждые 15 минут полностью пересобирает реестр и граф. Новый поддерживаемый файл появляется в таблице и графе без ручного вмешательства.

Ручной запуск:

```bash
python3 build_inventory.py
```

Проверка:

```bash
python3 -m unittest -v test_build_inventory.py
```
